[Strix](https://strix.ai) is an open-source AI pentester: it drives the target inside a Docker sandbox, exploits what it finds, and reports only what it can prove. Its model is set by an environment variable, and any OpenAI-compatible endpoint is a valid one.

## Install

```sh
curl -sSL https://strix.ai/install | bash
```

or, with uv, without the installer:

```sh
uv tool install strix-agent
```

Docker has to be running: the first scan pulls its sandbox image.

## Point it at Cyber v1

```sh
export STRIX_LLM="openai/nodecode-cyber-v1"
export LLM_API_BASE="https://api.nodecode.ai/v1"
export LLM_API_KEY="sk-nc-..."

strix --target ./app
```

`STRIX_LLM` is `<provider>/<model>`, and `openai/` is the provider that means "an OpenAI-compatible endpoint at `LLM_API_BASE`", so nothing here needs Strix to know our name. `LLM_API_KEY` is sent as the bearer token.

## What a scan spends

Strix prices a model from LiteLLM's table, which has no entry for this one, so give it [Cyber v1's prices](pricing.mdx#what-a-call-costs) in dollars per million tokens. These variables need Strix 1.7.1 or later:

```sh
export STRIX_LLM_INPUT_COST_PER_MTOK="0.33"
export STRIX_LLM_CACHED_INPUT_COST_PER_MTOK="0.009"
export STRIX_LLM_OUTPUT_COST_PER_MTOK="1.32"
```

They are the weekday prices. From Friday 00:00 to Monday 00:00 Amsterdam time every token costs half, so a weekend scan costs half of what Strix reports, and they leave out the 4x cached price a request pays above 262,144 input tokens.

With them set, Strix reports what a scan costs as it runs, and an agentic loop is a very cacheable one: on a 37-line Flask app in quick mode, Strix 1.7.1 made 258 requests in 9 minutes, 20.7M input tokens of which 19.96M were cache hits, and 122.7k output tokens, and reported $0.59 on 2026-11-26, a weekday. Nearly all of the input is the same prefix on every call, so the cached-input price does the work and the full input price pays for the 0.7M that differed.

## Where its sandbox cannot read

The target is mounted into a container that runs under `container_t`, and on a host with SELinux enforcing that context cannot read every path. A target under `/tmp` (`user_tmp_t`) and one under `/data` (`default_t`) both came back as files Strix could `stat` but not `open`, and its own report says so instead of pretending it looked. A target in your home is the ordinary case and works.

## Bounding it

```sh
strix --target ./app --instruction "Find the SQL injection and prove it with a live request." \
      -m quick --max-turns 60 --max-budget 1.00
```

A reasoning model spends tokens before it answers, so a turn limit in the single digits ends a scan in the middle of the reconnaissance. `--max-budget` is in dollars, counted at the prices above, and stops it there.
