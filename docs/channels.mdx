```sh
nodecode gateway setup discord    # or telegram, slack
```

The command lists the steps to take on the platform's side, takes the bot's token, asks who the bot should answer, and starts the bot. The bot runs inside Nodecode, so if Nodecode is not running, the command offers to turn the gateway on first.

## In the terminal

<Transcript name="setup-discord" />

Nodecode does not echo the token as you paste it. It keeps the token in a private file, never in the config, and checks it right away. You pick channels by number from the ones the bot can see. The bot will not start until you allow at least one channel, user or role.

<Mistakes>
<Mistake>
<What>A wrong or reset token</What>
<Why>`token: unauthorized (401): the token is wrong or revoked; reset it on the Bot page of the developer portal and save the new one`</Why>
<Instead>Reset the token and run the same command again. It picks up from what it already saved.</Instead>
</Mistake>
</Mistakes>

## Who it answers

The bot answers only the channels, users and roles you picked, and in a channel only when someone mentions it. If a stranger messages it directly, it replies with a pairing code, and `/channels` lets that person in: its row asks for the code. See [Safety and trust](security.mdx).

## Change it later

| Where | How |
| --- | --- |
| Terminal | Run `nodecode gateway setup discord` again |
| Shell | `/settings` > Channels, for Discord and Telegram |
| Web page | `nodecode web` > Control > Channels |
| A session | Say `set up discord` |

`/channels` shows the state of each channel and the people you let in, each with a row that removes them.

## More channels

Matrix, email, WhatsApp, iMessage and X channels are cells on the hub (<CellsTab />). Add one first, then set it up with the same command:

```sh
nodecode add nc://channel-matrix
nodecode gateway setup matrix
```
