Type `/` in the composer for the list. `/help` shows it with the key bindings.

A command is its name. Nothing is typed after it: typed alone, it offers what it does as choices. That is its sheet, or a list whose rows run when picked, or a row that asks for one line of text, such as a name or a path. In the shell the composer takes that text under the row's label; Enter runs it, and Esc puts it away and gives back the draft it stood over. Tab completes a name, and Enter runs it.

## Headless

A headless command answers without the shell, the terminal UI.

| Surface | How |
| --- | --- |
| Web page | Type the command in the page's composer, by its name. An alias, or a command with no headless arm, goes to the model. |
| Chat room | Send the command as a message, or pick it from the platform's command menu. |
| Eval | `(slash "/undo")` |

Typed alone in a chat room or on the web page, a command answers its choices: a room draws them as buttons, and a row that asks for text asks for it there. Eval gets them as text, a line a row, and the dialog as the second value.

In a chat room or eval, a shell-only command answers `/name needs an interactive shell`.

| --- | --- | --- |
| `/help` | Shows commands and key bindings. | Yes |
| `/clear`, `/new` | Starts a fresh session. Headless: moves this session back to its start. | Yes |
| `/sessions`, `/agents` | Opens the session picker. | No |
| `/rename` | Shows the session's name, asks for a new one (64 characters at most), or gives back the name the first prompt makes. | Yes |
| `/export` | Saves the session as Markdown: in this shell's folder, or in a folder or at a file it asks for. | No |
| `/execs` | Shows an exec's output. Ctrl+X or Delete interrupts it. | No |
| `/tree`, `/checkpoints` | Opens the session tree. Continue from a turn, or rewind. | No |
| `/undo` | Rewinds the last turn. | Yes |
| `/redo` | Returns to the branch the last rewind left. | Yes |
| `/fork` | Forks a new session at the current head. | No |
| `/history` | Picks a past prompt into the composer. | No |
| `/themes` | Lists themes, each previewed as it is highlighted; Enter switches to it. | No |
| `/settings` | Browses and changes settings. | No |
| `/models` | Shows or changes the main, auxiliary and decider models, and the backups. | Yes |
| `/evict`, `/compact` | Drops the oldest turns from the provider context: half of the retained history (the first row), a quarter, three quarters or all of it, or every retained turn through one picked from `/context`'s history. | Yes |
| `/context` | Shows this session's context window and usage. A part opens to what it holds, history to its turns. | Yes |
| `/status` | Nodecode right now: attention, runtime, services and today's usage. | Yes |
| `/usage` | Reports spend across sessions, a session's title and the other side calls included: today, 7 days, 30 days or all, 7 days first. Signed in to nodecode.ai, the shell shows the account first: the plan's requests left and the API credit. | Yes |
| `/login` | Signs in to your nodecode.ai account, to run on its API credit. Same as `nodecode login`. | No |
| `/logout` | Signs this machine out of your nodecode.ai account: its key stops working there, the key leaves this home's `auth.json` and the footer's meter goes. Same as `nodecode logout`. | No |
| `/details` | Offers the Developer and Standard viewports, the one in use marked; Ctrl+O switches them too. | No |
| `/cells` | Every cell: turn one on or off, see why one failed, make a new one. Headless: this process's cell report. | Yes |
| `/generations` | The history of this organism, and the way back to a change in it. | Yes |
| `/snapshot` | Takes a snapshot now: this organism's memory whole, values and all, under a dated name, and runs on from it. It holds this machine's keys, so it never leaves it. | Yes |
| `/snapshots` | Your snapshots, newest first, and Fresh from files. Enter switches to one in place, F2 renames one, Delete removes one after a confirm. | Yes |
| `/doctor` | Lists what is missing, with the remedy. | Yes |
| `/backup` | Archives the home under `~/.nodecode/backups/`. The archive holds your keys. The web page's Settings pane lists, downloads and restores them. | Yes |
| `/profile`, `/profiles` | The roster of profiles: switch to one, and what else a profile can do on its rows; `+ New profile` makes another. | Yes |
| `/gateway` | Where the gateway stands, then turning it on or off, a restart, its log, and setting up Discord, Telegram or Slack. What `nodecode gateway` does. | No |
| `/web` | Same as `nodecode web`. | No |
| `/setup` | Opens the setup walk. | No |
| `/think`, `/effort` | The model's reasoning rungs, the one in use marked; Default uses the model's own. | Yes |
| `/gc` | Shows garbage collection and stall stats, or starts a fresh window to count them in. | Yes |
| `/exit`, `/quit` | Exits the shell. | No |
| `/index` | What you keep: the meter and the picker, a search through it, files too, and a fresh pin. `$` at the start of a word opens it. | Yes |
| `/import` | Brings another coding agent's home into this one: it asks where to read from, previews what would land, then applies it. Its skills are linked and read where they are. The repositories an import holds are listed there, each one to take back. | Yes |

The gateway registers `/index` itself as it serves. It is no cell's.

| Command | Shell and headless differ |
| --- | --- |
| `/clear` | Shell: opens a new session. Headless: rewinds this session to its start. `/redo` returns. |
| `/undo` | Shell: restores files too. Headless: moves the conversation only. |
| `/models` | Shell: a picker with Main, Auxiliary, Decider and Backup tabs. A new provider is connected there; Ctrl+E replaces a key. Backup is the failover chain. Headless: the same choices as rows. |
| `/generations` | Shell: a sheet of the changes; Enter asks in place, then restores. Headless: one card of the changes to page and pick from; a pick asks first, then restores, or keeps or discards uncommitted edits that hold it. |
| `/context` | Shell: a grid, each part opening to what it holds. Chat room: one card that wears the window's state, from fine to past the eviction line. |
| `/login` | Shell only. No chat room or web page can sign this home in to an account. |
| `/logout` | Shell only. No chat room or web page can sign this home out. |

## Cell

A cell is a folder of code under `~/.nodecode/cells/`. Its command exists while the cell runs. Every cell command is headless.

A built-in wins over a cell command of the same name. A cell's command is its name too: typed alone, it answers its choices as a dialog, whose rows run its lines or ask for a line of text.

A cell adds its own commands with the `:command` clause. See [Cell API](cell-api.mdx#define-cell). The cells you can add are listed under <CellsTab />.
