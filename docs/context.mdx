Most agents only add to their context, until something summarizes it or cuts it. Nodecode's agent edits its own, the way a [Context Language Model](https://arxiv.org/abs/2609.37725) does.

<Recording name="selfedit" />

Asked why customers were charged twice, it reads four logs and blames the retries. Told that retries are off, it finds the real cause. Before it answers, it cleans up after itself:

1. It rewrites its wrong answer in its own context, so nothing after it leans on it.
2. It drops the four logs that misled it. The context goes from 35k tokens to 3k.

Nothing it drops is lost. Every word stays in the session's log, and the agent reads any of it back when it needs it.

{/* source: src/engine/working-context.lisp */}
## How

- `(context)` hands the agent its context as a file. What the file says is what the next request sends.
- `(context :drop '(15 21) :note "...")` makes the same edit in one call.
- If the window passes 85% and the agent has not made room, the oldest finished turns leave by themselves. They can still be read back.

The shell shows each edit as one row:

```
Context ~28.6k → ~489 tokens · 5 removed · by the model
```
