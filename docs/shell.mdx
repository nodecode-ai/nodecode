The shell is the terminal UI. It attaches to the gateway, the local server of a running Nodecode.

{/* source: src/client/client.lisp */}
## Turn

A turn is one prompt and the work the model does to answer it. One turn runs per session at a time.

| Action | Result |
| --- | --- |
| Enter, no turn running | Starts a turn. |
| Enter, turn running | Steers. The running turn ends at its next round boundary. Your message runs next. |
| Tab, turn running | Queues the prompt behind the running turn. |
| Up, a prompt is queued | Takes the newest queued prompt back into the composer. |
| Enter on an empty composer, after Up took a prompt back | Drops that prompt. |
| Esc, turn running | Interrupts the turn. |
| Esc, the turn produced nothing | The prompt returns to the composer. Applies to a turn this shell started. |
| Ctrl+C | Clears the composer. Empty composer: interrupts the turn. No turn: quits. |
| Left, empty composer | Leaves the session running. Opens `/sessions` on a fresh session. |

## Composer prefixes

| Prefix | Opens |
| --- | --- |
| `/` | The command dropdown. See [Slash commands](slash-commands.mdx). |
| `@` | Workspace file completion. Hidden files, `node_modules`, `target`, `zig-cache`, `zig-out`, `bazel-bin`, `bazel-out` and `bazel-testlogs` are skipped. At most 512 files, 10 folders deep. A path that starts with `~/`, `../`, `./` or `/` (on Windows also `C:\` and `\`) completes from that one folder instead, as a shell does: a folder goes on into it, and hidden names show once you type the leading `.`. |

## Footer

Windows under 12 rows have no footer.

| Side | Shows |
| --- | --- |
| Left | `provider model (effort) · ← sessions` |
| Left, sessions running | `← sessions · N running` |
| Left, target unknown yet | `setting up…` |
| Left, no model configured | `run /setup to add a model` |
| Right | `profile · folder · Gateway` |
| Right, signed in to nodecode.ai | The account's meter first: the plan's name, then its requests left, or the API credit once that pays. An unlimited account reads `Unlimited ∞`. |

Every part is a link. A second click on one closes the dialog it opened.

| Part | Opens |
| --- | --- |
| The model | `/models` |
| `(effort)` | `/think` |
| `← sessions` | `/sessions` |
| The account's meter | `/usage`, the account first |
| The profile | `/profiles` |
| The folder | The folder, as a `file://` link |
| `Gateway` | The web page, on Sessions |

The meter's colour says what pays: the plan with a tenth or more left; low once under a tenth, or when a spent plan's credit pays; danger when nothing can pay. `Gateway`'s colour alone shows the connection: connected, connecting or reconnecting, failed. A narrow window drops the profile and the folder, then the meter, then `Gateway`. Sign in with [`nodecode login`](cli.mdx#login) or `/login`.

## Turn bar

The bar shows while a turn runs.

| Part | Meaning |
| --- | --- |
| Spinner | The turn is running. |
| Verb | The current activity, `waiting on the model`, or the retry status. A 429 or 5xx retry adds `/models to switch`. |
| Clock | Elapsed time. |
| `quiet N` | How long a quiet stream has waited. |
| Token meter | Tokens of this turn. Developer viewport only. |
| `ctx N%` | Context use. Shown from 75%. |
| Stop key | `esc stop` |

While a turn runs, type into the composer to steer it. With text in it, the composer shows `enter steer` and `tab queue`.

A failed or interrupted turn leaves a resting bar with elapsed time and outcome.

## keybinds.json

Override keys in `~/.nodecode/keybinds.json`. The file is one JSON object: action name to chord.

Example: `{"toggle_viewport": "ctrl+t", "help": "none"}`.

A key that starts with `/` binds a slash line instead of an action: `{"/details developer": "ctrl+g"}`. The chord runs the line as if typed and entered, built-in or cell command alike, and leaves the composer's text where it stands.

| Slash binding rule | Detail |
| --- | --- |
| Collision | An action's chord, default or overridden, wins: the binding is dropped. Without ctrl a letter's case stands in for shift, so `alt+shift+r` collides with `alt+r`. With ctrl the shift decides: `ctrl+shift+y` binds beside `ctrl+y`, and answers only in a terminal that reports the shift (the kitty keyboard protocol: Ghostty and kitty, WezTerm with `enable_kitty_keyboard`); elsewhere the press arrives as `ctrl+y`. |
| Editing keys | A binding is read before the composer, so it takes a chord such as `alt+u` from it. |
| Typing keys | A chord with neither `ctrl` nor `alt` binds only F1 to F12; `q` or `shift+x` would take a letter from typing, so the binding is dropped. |
| Open dialog | The dialog keeps its keys; the binding waits. |
| Unknown command | Pressing the chord says so in the composer status. |
| Malformed chord | The binding is dropped. |

| Rule | Detail |
| --- | --- |
| Chord | Modifiers `ctrl` (or `mod`), `alt`, `shift` and one key, joined by `+`. |
| Key names | `enter`, `tab`, `esc`, `backspace`, `delete`, `up`, `down`, `left`, `right`, `space`, `pgup`, `pgdn`, `home`, `end`, `f1` to `f12`, or one character. |
| Override | One chord replaces every default chord of that action. |
| `"none"` | Unbinds the action. |
| Malformed chord | The defaults stay. |
| Unreadable file | Ignored. |

| Action name | Default |
| --- | --- |
| `quit` | `ctrl+q`, `ctrl+d` |
| `submit` | `enter` |
| `submit_turn_queue` | `tab` |
| `insert_newline` | `shift+enter`, `alt+enter`, `ctrl+j` |
| `accept_suggestion` | `tab` |
| `history_previous` | `up` |
| `history_next` | `down` |
| `history_dialog` | `ctrl+r` |
| `sessions_dialog` | `ctrl+s` |
| `rename` | `f2` |
| `toggle_viewport` | `ctrl+o` |
| `toggle_dialog_fullscreen` | `ctrl+f` |
| `page_up` | `pgup` |
| `page_down` | `pgdn` |
| `scroll_home` | `home` |
| `scroll_end` | `end` |
| `help` | `?` |
| `open_command_palette` | `ctrl+p` |
| `paste_image` | `ctrl+v`, `ctrl+alt+v` |
| `copy_selection` | `ctrl+shift+c` |
