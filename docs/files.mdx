## The home

The home is `~/.nodecode/`. This one has had an afternoon: four turns, one key, one `/backup` and one profile. In it are <Step name="home-store">the store</Step> and <Step name="home-lock">its lock</Step>, <Step name="home-layer">the layer</Step> of kept definitions, <Step name="home-knowledge">the knowledge cell</Step> of memories and skills, <Step name="home-gens">a generation per keep</Step>, and <Step name="home-keys">two files that are keys</Step>.

## Settings

Files you or the agent write on purpose. A profile carries them. A plain export carries all but `auth.json` and `secrets/`.

| Entry | Holds |
| --- | --- |
| `config.jsonc` | The settings. See [Config](/config). |
| `AGENTS.md` | Your rules for every session. See [Instruction files](/instructions). |
| `SOUL.md` | The persona channel bots speak in. |
| `themes.json` | Your own themes. |
| `auth.json` | Provider keys, at `api_keys.<id>.key`. `/models` writes it when you connect a provider, and `nodecode login` writes your nodecode.ai account's key. |
| `secrets/` | Secrets pasted into `/settings`, one 0600 file each. |
| `cells/` | Cell folders. See [Cells](/cells). |
| `cells/<you>/` | The layer: the definitions the agent kept, one file each. A git repository. |
| `cells/<you>-memory/` | The knowledge cell: memories and skills, kept as definitions. Read by the index, never loaded. |
| `profile.jsonc` | The profile's manifest: what this profile is. |

`<you>` is git's `user.name` in lowercase, each run of other characters one hyphen: `Mike Smith` is `mike-smith`. Without one it is `USER`, then `you`.

<Mistakes>
<Mistake>
<What>Writing a key into `config.jsonc` as `api_key`</What>
<Why>An export and a new profile carry `config.jsonc`, key and all, and no mode is forced on it.</Why>
<Instead>`/models`. The key goes in `auth.json`, 0600, which an export leaves out.</Instead>
</Mistake>
<Mistake>
<What>Keeping `~/.nodecode` in a dotfiles repository</What>
<Why>It carries `auth.json`, `operator-token` and the store.</Why>
<Instead>`nodecode profile export NAME PATH`: the settings and the cells, no store, no keys.</Instead>
</Mistake>
</Mistakes>

<Sides>
<Side tag="mistake">

<Run typed mark="api_key">

```output

```

</Run>

The plain export, the one meant for sharing, has the key in it.

</Side>
<Side tag="instead">

<Run typed mark="^0$">

```output
~$ nodecode profile export default ~/share2.tar.gz && tar xzf ~/share2.tar.gz -O | grep -c sk-new
exported default to /home/you/share2.tar.gz
0
```

</Run>

</Side>
</Sides>

## State

Files Nodecode makes for itself. A new profile starts without them, and an export leaves them out, except `cells/.locks/`, which rides inside `cells/`.

| Entry | Holds |
| --- | --- |
| `history.db` | The store: every session and every event. SQLite, with `-wal` and `-shm` beside it. |
| `history.db.lock` | Held by the process that owns the store, for as long as it runs. |
| `history.db.owner` | That process's pid and gateway port, as JSON. |
| `history.db.stdio.log` | The organism's boot log and stray output. |
| `operator-token` | The gateway token. See [Safety and trust](/security). |
| `usage.jsonl` | Each keep, view and call of a memory or skill. The index ranks by it. |
| `generations/` | A manifest per sealed generation, a restore's markers, and in `objects/` and `trees/` the bytes of folders no commit puts back. |
| `release-pin` | The release `nodecode update VERSION` holds this home at. A bare `nodecode update` lifts it. |
| `keybinds.json` | Key overrides. See [The shell](/shell). |
| `trust.json` | The folders you trusted or refused. See [Instruction files](/instructions). |
| `theme-selection` | The theme picked with `/themes`. |
| `composer-history` | Prompts you typed. |
| `composer-catalogs.sexp` | The lists `@` and `/` complete from, as last read. |
| `cells-named` | Shipped cells already named as not installed. |
| `distribution.json` | Where this home was installed from. |
| `gateway-off` | The background gateway's off switch. |
| `import/` | The import's marker and its reports. |
| `hub/` | The cell index, as last read. |
| `cells/.locks/` | Write locks of the knowledge cells. |
| `mcp/` | MCP servers' error logs, `mcp/<name>.stderr.log`. |
| `link/state.json` | This machine's name at its relay, and the browsers let in. |
| `backups/` | `/backup`'s archives, each with a `.json` note. |
| `context/` | Each session's working context copy. |
| `changes-seen` | The release whose Latest changes `/settings` last showed. |
| `team/`, `boards/`, `chrome-extension/`, `chrome-screenshots/` | Written by the team, board and chrome cells. |

## The store

While Nodecode runs, <Step name="wal-db">`history.db` is a header</Step> and <Step name="wal-wal">the sessions are in `-wal`</Step>. The lock names who owns them: <Step name="own-pid">a pid</Step> and <Step name="own-port">a port</Step>. Every shell you open attaches to that one.

<Run typed light={{ "wal-db": "4\\.0K", "wal-wal": "3\\.6M" }}>

```output
~$ ls -lh ~/.nodecode/history.db*
-rw-r--r-- 1 you you 4.0K Oct  8 21:18 /home/you/.nodecode/history.db
-rw-r--r-- 1 you you  32K Oct  8 21:18 /home/you/.nodecode/history.db-shm
-rw-r--r-- 1 you you 3.6M Oct  8 21:19 /home/you/.nodecode/history.db-wal
-rw------- 1 you you    0 Oct  8 21:18 /home/you/.nodecode/history.db.lock
-rw------- 1 you you   38 Oct  8 21:18 /home/you/.nodecode/history.db.owner
-rw-r--r-- 1 you you  217 Oct  8 21:18 /home/you/.nodecode/history.db.stdio.log
```

</Run>

<Run typed light={{ "own-pid": "\"pid\"", "own-port": "\"port\"" }}>

```output
~$ cat ~/.nodecode/history.db.owner
{
  "pid": 2212192,
  "port": 37213
}
```

</Run>

<Mistakes>
<Mistake>
<What>Copying `history.db` while Nodecode runs</What>
<Why>You get the header and none of the sessions: `no such table: events`.</Why>
<Instead>`nodecode profile export NAME PATH --whole`, or `/backup`. Both take a whole copy of the store while it runs.</Instead>
</Mistake>
<Mistake>
<What>Deleting `history.db.lock`</What>
<Why>A second organism takes the same store on another port. When it stops it deletes `history.db.owner`, and the shells lose the first.</Why>
<Instead>Nothing to clear. The lock goes with the process that holds it, crash or not. `nodecode profile list` shows who holds it.</Instead>
</Mistake>
</Mistakes>

<Sides>
<Side tag="mistake">


</Run>

## The layer

Each definition the agent keeps is a file in `cells/<you>/` and <Step name="log-commit">a commit</Step>, and each keep seals <Step name="gen-current">a generation</Step>. To go back, roll back to one. A rollback puts back your side alone, the layer and the other folders the generation recorded. The binary and its shipped cells stay on the release this build runs.

<Run typed light={{ "log-commit": "^[0-9a-f]{7} " }}>

```output
~$ git -C ~/.nodecode/cells/you log --oneline
b453153 (HEAD -> master) word-count — session s-8ZRLUFP8
12d29ea count-lines — session s-8ZRLUFP8
```

</Run>

<Run typed light={{ "gen-current": "^generation \\d+" }}>

```output
~$ nodecode generations
generation 3  current  2026-10-09T04:19:20.188Z  nodecode 0.0.1+370099410
  you layer own b453153  +1 keep since 2
generation 2  2026-10-09T04:18:49.964Z  nodecode 0.0.1+370099410
  you layer own 12d29ea
  added since 1: you
generation 1  2026-10-09T04:18:44.853Z  nodecode 0.0.1+370099410
```

</Run>

<Mistakes>
<Mistake>
<What>Deleting a kept file to take a definition back</What>
<Why>The folder now has an edit nothing versions, and a rollback refuses until it is gone.</Why>
<Instead>`nodecode rollback N` to the generation before it. The layer takes one commit forward, and its history stays.</Instead>
</Mistake>
</Mistakes>

<Sides>
<Side tag="mistake">

<Run typed mark="uncommitted edits">

```output
~$ rm ~/.nodecode/cells/you/word-count.lisp && nodecode rollback 2

```

</Run>

</Side>
<Side tag="instead">

<Run typed mark="restored">

```output
~$ nodecode rollback 2
generation 2 restored: you at 12d29ea; the next launch runs it
```

</Run>

<Run typed mark="restored generation">

```output
~$ git -C ~/.nodecode/cells/you log --oneline && ls ~/.nodecode/cells/you
854f3fa (HEAD -> master) restored generation 2 -- session s-GATEWAY
b453153 word-count — session s-8ZRLUFP8
12d29ea count-lines — session s-8ZRLUFP8
count-lines.lisp  you.asd
```

</Run>

</Side>
</Sides>

## Profiles

A new profile copies the settings and <Step name="links">links what is yours</Step>: `auth.json`, `secrets/` and every knowledge cell. It gets a fresh store and a fresh layer. `--clone-all` copies the keys and clones the layer instead. See [Profiles](/profiles).

<Run typed light={{ "links": "-> /home/you/" }}>

```output
~$ ls -l ~/.nodecode/profiles/work ~/.nodecode/profiles/work/cells

drwxr-xr-x 2 you you  60 Oct  8 21:19 cells
-rw-r--r-- 1 you you 548 Oct  8 21:19 config.jsonc
-rw-r--r-- 1 you you 193 Oct  8 21:19 profile.jsonc

lrwxrwxrwx 1 you you 37 Oct  8 21:19 you-memory -> /home/you/.nodecode/cells/you-memory/
```

| Only in the default home | Holds |
| --- | --- |
| `profiles/<name>/` | The home of each named profile. |
| `active-profile` | The profile a bare `nodecode` boots. `nodecode profile use` writes it. |

## Outside the home

| Path | Holds |
| --- | --- |
| `<project>/.nodecode/workspace_snapshots` | Snapshots for undo, in each folder a session edits. Never in your home folder or `/`. See [Sessions and undo](/sessions). |
| `~/.local/share/nodecode/` | The installed releases. On Windows, `%LOCALAPPDATA%\Programs\nodecode`. See [Install](/install). |
| `~/.local/bin/<profile>` | The command `profile create` writes for a profile. |
| `nodecode-gateway.service` | The background gateway, in `~/.config/systemd/user/`. A named profile's is `nodecode-gateway-NAME.service`. On macOS, a plist in `~/Library/LaunchAgents/` and its log in `~/Library/Logs/nodecode/`. |
| `nodecode-ephemeral-<pid>.db` | The store of an `--ephemeral` run, in the temp folder. |

Nodecode does not add `.nodecode/` to your project's ignore list. Until you do, <Step name="untracked">git sees it</Step>.

<Run typed light={{ "untracked": "\\?\\? \\.nodecode/" }}>

```output
~/project$ git status --short && du -sh .nodecode
 M src/main.rs
?? .nodecode/
128K	.nodecode
```

</Run>

<Mistakes>
<Mistake>

<Why>The snapshot repository goes into your commit: 30 files after one edit.</Why>
<Instead>Add `.nodecode/` to `.gitignore`, or to `.git/info/exclude` to keep it to yourself.</Instead>
</Mistake>
</Mistakes>

## Cache

What Nodecode can fetch or build again. Every profile shares it. Most of it is <Step name="cache-warm">the launch images</Step>; the home itself is <Step name="cache-home">a few megabytes</Step>.

<Run typed light={{ "cache-warm": "/warm$", "cache-home": "\\.nodecode$" }}>

```output
~$ du -sh ~/.cache/nodecode/* ~/.nodecode
16K	/home/you/.cache/nodecode/layers
7.5M	/home/you/.cache/nodecode/models.dev
158M	/home/you/.cache/nodecode/warm
4.0M	/home/you/.nodecode
```

</Run>

| Platform | Cache root |
| --- | --- |
| Linux, macOS | `$XDG_CACHE_HOME/nodecode/`, else `~/.cache/nodecode/` |
| Windows | `%LOCALAPPDATA%\nodecode\`, unless `XDG_CACHE_HOME` is set |

| Entry | Holds |
| --- | --- |
| `models.dev/api.json` | The models.dev catalog. |
| `provider-models.json` | Model lists fetched from providers. |
| `layers/`, `peripherals/` | The compiled layer and cells, per build. |
| `warm/` | Launch images. Linux and macOS. |
| `previews/` | Images a turn looked at, as they were then, and their PNG copies to show in the terminal. |
| `profile-import/`, `profile-install/` | Where a profile is unpacked before it moves in. |
| `leases/` | One lock per bot token, so two organisms never run one bot. |
| `channel-files/`, `channel-images/` | Channel attachments and images. |
| `card-pictures/` | Pictures for Discord cards. Gone after a day. |
| `libdave/`, `speaker/`, `transcriber/` | Discord's voice encryption, and the local voice and speech engines. |
| `prs/` | Scratch clones for the prs cell. |
| `open-url.log` | Output of the last link opener. |

<Mistakes>
<Mistake>
<What>Deleting `~/.nodecode` to free space</What>
<Why>That is the agent: its store, its layer, its keys. Here it is 4 MB.</Why>
<Instead>Clear the cache. `rm -rf ~/.cache/nodecode/warm` is always safe; the next launch builds it again.</Instead>
</Mistake>
</Mistakes>

## Permissions

The home is <Step name="mode-dir">yours alone</Step>, and so is <Step name="mode-key">every file that is a key</Step>. <Step name="mode-loose">`config.jsonc` keeps its mode</Step>.

<Run typed light={{ "mode-dir": "^drwx------", "mode-key": "^-rw-------", "mode-loose": "^-rw-r--r--" }}>

```output
~$ stat -c "%A  %n" ~/.nodecode ~/.nodecode/auth.json ~/.nodecode/operator-token ~/.nodecode/history.db.owner ~/.nodecode/backups ~/.nodecode/backups/* ~/.nodecode/config.jsonc
drwx------  /home/you/.nodecode
-rw-------  /home/you/.nodecode/auth.json
-rw-------  /home/you/.nodecode/operator-token
-rw-------  /home/you/.nodecode/history.db.owner
drwx------  /home/you/.nodecode/backups
-rw-------  /home/you/.nodecode/backups/nodecode-default-2026-10-08-211925.json
-rw-------  /home/you/.nodecode/backups/nodecode-default-2026-10-08-211925.tar.gz
-rw-r--r--  /home/you/.nodecode/config.jsonc
```

</Run>

| Path | Mode |
| --- | --- |
| `~/.nodecode/` | 0700. Set when the store opens, and again at every write of a key. |
| `auth.json`, `operator-token` | 0600, at every write. |
| Files in `secrets/` | 0600, in a 0700 folder. |
| `history.db.owner`, `history.db.lock` | 0600 |
| `link/state.json` | 0600, in a 0700 folder. |
| `backups/` | 0700. Each archive and note: 0600. |
| An `export --whole` archive | 0600 |
| `config.jsonc` | No mode is forced. A write keeps the file's mode. |

## Backups and exports

Three ways to take a home with you, and only one is for sharing.

<Tty name="backup" />

| Entry | New profile | `--clone-all` | Export | `--whole` | `/backup` |
| --- | --- | --- | --- | --- | --- |
| `config.jsonc`, `AGENTS.md`, `SOUL.md`, `themes.json` | Copied | Copied | Copied | Copied | Copied |
| `auth.json`, `secrets/` | Linked | Copied | No | Copied | Copied |
| `cells/<you>/`, the layer | New | Cloned | Copied | Copied | Copied |
| `cells/<you>-memory/` | Linked | Cloned | Copied | Copied | Copied |
| `history.db`, the store | New | New | No | Copied | Copied |
| `operator-token` and the rest of State | No | No | No | No | No |
